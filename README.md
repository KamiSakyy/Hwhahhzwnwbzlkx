# ✉️ ARI — первый self-hosted мессенджер

**Твой сервер. Твои данные. Сквозное шифрование.**
Конкурент Telegram/WhatsApp/Signal, который ты разворачиваешь сам за 1 клик.

- 📱 Android-приложение (Java + XML, Material 3, чёрная тема в стиле Telegram 2026)
- 🔐 **Сквозное шифрование**: X3DH + **Double Ratchet** (как Signal), AES-256-GCM.
  Сервер хранит только шифротекст и физически не может читать переписку
- 📷 Фото, 🎬 видео, ⭕ кружки, 🎤 голосовые — всё тоже шифруется на устройстве
- 🏠 **Self-hosted**: при первом запуске приложение спрашивает адрес ТВОЕГО сервера
- ⚖️ APK ≤ 8 МБ (release с minify + shrinkResources)

## 🚀 Сервер на Railway — одна кнопка

Railway → **New Project** → **Deploy from GitHub repo** → этот репозиторий → **Deploy**.
В корне лежит `Dockerfile` — Railway (2026) находит и использует его сам,
без railway.json (Config-as-Code устарел и отключён). Настроек не нужно.
Потом в Railway открой **Settings → Networking → Generate Domain** — это и есть
адрес сервера, который вводится в приложении.

### ⚠️ ЖЁСТКОЕ УСЛОВИЕ ПРО БАЗУ (так задумано!)

**Вся переписка и все данные лежат строго в `/app/messenger.db` внутри
контейнера** (плюс служебные `.db` там же). Никаких внешних баз и томов.
При редеплое Railway без тома база создаётся заново пустой — пользователи
регистрируются заново. Сервер при старте проверяет файл и **не запустится,
если `messenger.db` не создан**. Это обязательное условие архитектуры.

## 🏗 Структура

- `server.py` — сервер (FastAPI): auth, публичные ключи, шифротекст, зашифрованные медиа
- `app/` — Android-приложение (`com.ari.messenger`)
  - `Ratchet.java` — Double Ratchet, `Crypto.java` — P-256 ECDH/HKDF/AES-GCM
  - `ChatEngine.java` — X3DH-сессии, отправка/синхронизация, E2EE-медиа
- `.github/workflows/build-apk.yml` — сборка APK (Java 17, Gradle 8.7, Android SDK)
- `Dockerfile` — деплой сервера (Railway подхватывает его автоматически)

## 🔑 Как работает шифрование (честно)

1. При регистрации устройство генерирует identity- и prekey-пары (P-256),
   публичные уезжают на сервер, приватные никогда не покидают телефон.
2. Первый диалог: X3DH (3× ECDH) → общий секрет → Double Ratchet:
   каждое сообщение — свой ключ, цепочки хэшей, пропущенные сообщения
   расшифровываются из сохранённых ключей. Компрометация одного ключа
   не вскрывает ни прошлое (forward secrecy), ни будущее (post-compromise).
3. Медиа шифруется случайным AES-ключом, ключ летит внутри зашифрованного
   Ratchet-сообщения; на сервере лежит только шифротекст блоба.
