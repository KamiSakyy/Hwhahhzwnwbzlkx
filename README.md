# АРИ · мессенджер в одном сообщении Telegram

Небольшой текстовый мессенджер на Telegram Bot API. У каждого пользователя есть одно сохранённое сообщение-экран: после первого запуска бот редактирует именно его, а не отправляет новое сообщение при каждом действии или получении чата. Новые сообщения сохраняются в SQLite и обновляют экран собеседника, если тот уже начал диалог с ботом.

Исходники и Dockerfile находятся в корне репозитория, как требуется Railway.

## Возможности

- Регистрация по почте, паролю и уникальному юзернейму `@name`.
- Вход по почте и паролю; аккаунт привязывается к Telegram-профилю.
- Поиск пользователей по `@юзернейму` и текстовые диалоги.
- Список диалогов, история последних сообщений и счётчик непрочитанного.
- Один редактируемый экран бота на Telegram-пользователя. Если пользователь удалил экран, бот создаст замену при следующем обращении.
- SQLite-хранилище; на Railway его нужно разместить на Volume.
- `/health` и `PORT` для Railway.

Регистрация идёт по шагам: почта → пароль → уникальный `@юзернейм`; после неё пользователь сразу входит в новый аккаунт. Почта не проверяется письмом, восстановления пароля и удаления аккаунта пока нет.

Это MVP для **текстовых личных диалогов**: группы, фото, файлы, аудио и звонки не поддерживаются. Сообщения переписки лежат в SQLite без шифрования на уровне приложения. Перед открытым запуском добавьте политику конфиденциальности, правила хранения/удаления данных, резервные копии и модерацию. Для работы с одним bot token оставляйте только один запущенный экземпляр приложения.

## Важно о токене и паролях

**Токен бота, присланный в переписке, следует считать скомпрометированным.** Отзовите его в `@BotFather`, выпустите новый и используйте только новый токен. Не добавляйте токен в исходный код, Git, Docker image или README.

В Railway задайте секретную переменную `TELEGRAM_BOT_TOKEN` через **Service → Variables**. Локально скопируйте `.env.example` в `.env` и вставьте новый токен; файл `.env` исключён из Git.

Пароли сохраняются в базе только как PBKDF2-SHA256 salted-хеши и не выводятся в логи или в интерфейс. Бот старается удалить сообщения с почтой и паролем через Telegram Bot API, но удаление — **best effort** и не гарантируется. Переписка с Telegram-ботом не является сквозным E2E-шифрованием; не вводите пароль, который используете для почты или других сайтов.

## Команды

Можно писать команды обычным текстом или использовать slash-команды:

| Действие | Текст | Команда |
| --- | --- | --- |
| Начало / экран | `/start` | `/start` |
| Регистрация | `регистрация` | `/register` |
| Вход | `войти` | `/login` |
| Поиск | `поиск` | `/search` |
| Диалоги | `входящие` | `/inbox` |
| Профиль | `профиль` | `/profile` |
| Назад | `назад` | `/back` |
| Выйти и отвязать Telegram | `выйти` | `/logout` |
| Отменить ввод | `отмена` | `/cancel` |
| Справка | `помощь` | `/help` |

После `поиск` введите `@юзернейм`. В открытом диалоге обычный текст отправляется собеседнику. Чтобы сменить диалог, снова напишите `поиск`.

## Запуск локально

Нужен Python 3.12+.

```bash
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
cp .env.example .env            # затем задайте TELEGRAM_BOT_TOKEN в .env
set -a && . ./.env && set +a    # Bash; в Windows задайте переменные отдельно
python main.py
```

Бот использует long polling Telegram и запускает HTTP health endpoint на `0.0.0.0:$PORT` (локально по умолчанию порт `8080`). Для локальной базы задаётся `DATABASE_PATH=./messenger.sqlite3`.

Проверки:

```bash
python -m unittest -v
```

## Развёртывание на Railway — без консоли и команд

Проверено по официальной документации Railway **16 октября 2026**. Корневой `Dockerfile` Railway обнаруживает сам; он также уже задаёт запуск приложения, `PORT` и путь к базе. `railway.json`, ручная команда запуска и настройка healthcheck для старта не нужны.

Для запуска из телефона:

1. В Railway создайте проект из этого GitHub-репозитория — выберите репозиторий и нажмите **Deploy**.
2. Единственный обязательный секрет — `TELEGRAM_BOT_TOKEN` в **Variables**. Используйте новый токен из BotFather; старый уже раскрыт в чате.
3. Чтобы аккаунты и сообщения переживали новый деплой, один раз добавьте Volume с mount path `/data`. Без Volume приложение запустится, но Railway может удалить SQLite-файл при пересоздании контейнера.

Не нужно вводить `DATABASE_PATH`, `PORT`, команды или запускать терминал. Достаточно оставить одну replica (это Railway default для нового сервиса). После запуска напишите боту `/start`.

### Важное о «бесплатно» в Railway

По опубликованным Railway тарифам на дату проверки план Free даёт **$1 ежемесячного usage credit**, а пробный период — разовый кредит **$5 до 30 дней**; это не гарантия постоянной бесплатной работы. Использование CPU, RAM и Volume может исчерпать кредит, после чего сервис может остановиться. На бесплатном плане документация указывает ограниченный объём Volume (0.5 GB). Условия и лимиты могут измениться — проверьте актуальный Dashboard и страницу тарифов перед запуском.

У некоторых аккаунтов Trial исходящий сетевой доступ ограничен. Для long polling бот должен подключаться к Telegram Bot API; если соединение блокируется, завершите проверку Railway/GitHub или используйте тариф с нужным сетевым доступом.
