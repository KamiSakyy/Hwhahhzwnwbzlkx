# Текущее состояние — НЕ готовый продукт

## Ограничения пользователя
- Никаких эмуляторов.
- Никаких новых APK до завершения проекта.
- Java/XML, настоящий код DrKLO/Telegram, не Canvas-имитация.
- Дальнейшая release-сборка только GitHub Actions; arm64, <=10 МБ, без Secrets.

## Реализовано в исходниках новой интеграции
- Закреплённый официальный подмодуль DrKLO/Telegram от 13.10.2026.
- Наследник официального ThemePreviewActivity, официальный render pipeline.
- Host официального INavigationLayout в уже инициализированном Telegram runtime.
- Выбор тела сообщения/ссылки/подписи медиа и фона пузыря по данным cell/layout.
- Официальный ColorPicker + alpha + AARRGGBB; Apply/Cancel/Default.
- Поиск по runtime-реестру ключей через Telegram RecyclerListView/TextColorCell.
- Инструменты редактора в обеих настоящих ActionBar; сохранение оригинальных
  callbacks, undo/redo, снятие добавленных пунктов при закрытии.
- Закрытие редакторских диалогов при уничтожении preview, восстановление общих
  paints, отключение выбора во время изменения размеров пузыря.
- Source/JVM CI без Android-устройств. Ранее ядро прошло 30 JVM assertions.
- Заблокированы APK workflows и packaging/device задачи Gradle.

## НЕ выполнено / НЕ подтверждено
- Старый `app/` НЕ является новым entry point. Добавлен отдельный upstream
  `:ThemeStudioHost` с EditorActivity и XML-контейнером; компиляция ещё не подтверждена.
- Standalone offline bootstrap без аккаунта и побочных сетевых действий.
- Компиляция Android-интеграции с полной upstream dependency graph.
- Выбор каждого элемента: timestamp, reply/quote/code, реакции, media-controls,

- Импорт/экспорт/фотообои старого прототипа ещё не перенесены в новый host.
- Восстановление проекта/поворот и полный жизненный цикл на устройстве.
- Проверка визуальной идентичности, удобства, TalkBack на физическом устройстве.
- Проверенный размер новой реализации и безопасная production-подпись.

Файлы `integration/telegram` нельзя считать работающим готовым приложением
только потому, что исходники написаны. JVM-проверки не проверяют Android UI.

## Дизайн: отделение редактора от эталонного preview
В текущих исходниках EditorMenuController больше не добавляет пункты в ActionBar
Telegram и не заменяет его callbacks. Вместо этого отдельная XML-панель host
содержит Цвета/Отмена/Повтор/Просмотр. В чистом режиме она скрывается, перехват
нажатий редактором отключается; Back возвращает инструменты (включая callback
Android 13+). Оригинальная иерархия preview создаётся через super.createView.

ColorEditorController перенесён из AlertDialog в официальный Telegram BottomSheet
с оригинальным ColorPicker и ButtonWithCounterView. Затемнение выключено,
свайп-dismiss выключен во избежание конфликта с ползунком; действия вынесены в
непрокручиваемую нижнюю строку. Высота панели ограничена, сами поля прокручиваются.

Это изменения исходников новой интеграции, НЕ обновление старого APK в Handoff.
Сборок/эмулятора не было. Pixel-perfect совпадение и поведение на устройстве НЕ
подтверждены. Legacy app/ по-прежнему содержит отклонённый Canvas-прототип и не
является реализацией нового preview. Новый host всё ещё экспериментальный.

## Выбор свойств сообщения и жизненный цикл панели
- Resolver теперь распознаёт область reply по `replySelectorRect` оригинального
  ChatMessageCell (при наличии текущих reply layouts и стабильной геометрии).
- Для reply и пузыря открывается явный список свойств/связанных состояний с HEX
  и официальным ключом: фон, выделение, тень, текст, ссылки, время; для reply —
  имя, текст/подпись вложения, линии. Неизвестные upstream ключи не добавляются.
- Это НЕ попиксельное определение ключа времени или каждой буквы reply. Цвета
  reply могут быть производными от цвета собеседника; список обозначает возможные
  свойства, а не гарантирует влияние каждого ключа на каждый fixture.
- При переключении элемента старая транзакция откатывается синхронно, до открытия
  новой панели. Её поздний dismiss/callback больше не отменяет новую транзакцию;
  обработчики старых кнопок/ползунков блокируются после завершения транзакции.
- Touch-down/up привязаны не только к cell, но и к тому же MessageObject: повторно
  использованная RecyclerView cell не приводит к редактированию другого сообщения.
- Поиск элемента учитывает Z/elevation дочерних View. Произвольный custom drawing
  order/анимации/TalkBack ещё требуют проверки; полной поддержки не заявляется.

Эти изменения проверены чтением исходников и локальными source guards. Android
компиляция, APK, эмулятор и GitHub workflows не запускались.

## Числовой RGBA-ввод
В панели оригинального ColorPicker добавлен RgbaFields: четыре EditTextBoldCursor
с числовой клавиатурой, доступными подписями, диапазоном 0–255 и размером поля
48dp. Значения связаны с picker/alpha/HEX, сохраняются в той же транзакции.
Пустой/некорректный канал блокирует Apply; неполный ввод не записывается в модель.
При наборе сохраняется курсор активного поля. Callback завершённой панели не
применяет изменения после переключения на другой элемент.

Проверки в этом продолжении были только source guards / diff checks. Никакая
Android/Telegram-компиляция, новая APK или эмулятор не запускались. Поведение на
устройстве и визуальное совпадение по-прежнему не подтверждены.

## Геометрия оригинального экрана — исправление viewport
Ранее вертикальная LinearLayout отнимала 48dp у оригинального Telegram preview
даже в режиме редактирования. Это меняло высоту списка и положение нижних
элементов. Контейнер заменён на полноэкранный FrameLayout: upstream получает
match_parent по обеим осям, без весов, редакторских отступов и масштабирования.
Инструменты теперь отдельным overlay поверх нижней части, а не причиной reflow.
В чистом режиме overlay отсутствует. В режиме редактирования он всё ещё закрывает
нижние 48dp (не является частью Telegram); это не заявляется как полное визуальное
совпадение с оригиналом. Source guard проверяет отсутствие уменьшения viewport.
Статус/навигационная панели системы и реальный runtime требуют отдельной проверки.

## Начато фактическое выделение UI-only, не очередная упаковка клиента
`integration/ui-only` — отдельные settings и Android library без :TMessagesProj
и вообще без внешних runtime-зависимостей. Первый выделенный компонент:
`MessageDrawable.generatePath`, перенесённый побайтно из pinned upstream в
`UpstreamBubblePath`; геометрия хвоста/дуг/сгруппированных углов не заменялась.
Адаптер принимает density и layout state явно, вместо запуска AndroidUtilities /
SharedConfig / приложения Telegram. Исходный TYPE_PREVIEW dp factor 3 сохранён.
Происхождение/хеш метода и GPL license приложены.

`extract_bubble_geometry.py --check` подтверждает воспроизводимость и идентичность
самого метода; `check_ui_only_boundary.py` проверяет Android-graphics-only imports,
отсутствие клиентских зависимостей/native libs/permissions. Обе проверки PASS.
Это только компонент геометрии, НЕ готовый экран: текстовая компоновка, ActionBar,
список, composer, тени/градиенты и интеграция редактора ещё не выделены. Android
компиляции/сборки нового APK/эмулятора в этом продолжении не было.
