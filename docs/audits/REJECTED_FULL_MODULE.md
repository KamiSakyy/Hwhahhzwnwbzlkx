# Почему APK 86,914,199 bytes отклонён

Ошибка архитектуры: `integration/android-host/build.gradle` подключает
`implementation project(':TMessagesProj')`. Это весь library-модуль клиента,
а не выделенный набор элементов интерфейса. Отдельный launcher/удалённые
permissions не удаляют Java/native-код и транзитивные зависимости из APK.
Дополнительно у host release не были включены minify/shrinkResources.

Измерено по фактическому APK, **размеры внутри ZIP, десятичные MB**:

| Состав | Bytes | MB |
|---|---:|---:|
| resources.arsc | 26,838,960 | 26.84 |
| 2 arm64 native libraries | 23,158,360 | 23.16 |
| 7 DEX | 22,786,185 | 22.79 |
| res | 6,904,232 | 6.90 |
| assets | 6,369,786 | 6.37 |

Остаток: прочие записи, ZIP headers/alignment/signing. Точная машинная ведомость:
`rejected-full-module-apk.json`, воспроизводится `scripts/audit_apk_size.py`.
`libtmessages.49.so` содержит смешанную функциональность; неверно называть
все его 22,138,808 bytes исключительно протоколом. В APK также оказались
`liblanguage_id_l2c_jni.so`, language-id model и metadata Firebase, Maps, Cast,
Wallet, Billing, Wearable, MLKit — ненужные редактору зависимости.

## Решение по отвергнутой сборке

- Автоматический запуск `editor-apk.yml` удалён, job выключен даже при dispatch.
- Этот APK не является принятым результатом. Исторический файл оставлен для аудита,
  не переименован в «готовый компактный редактор».
- Полный pinned checkout Telegram остаётся исходным эталоном, не набором
  зависимостей для доставки. Пользователь требовал исходники, не весь клиент в APK.
- Включение R8 само по себе не исправляет границу модулей: точка входа
  ApplicationLoader и исходный ThemePreviewActivity ведут к контроллерам клиента.

## Граница необходимой замены (пока НЕ реализована)

Отдельный UI-only модуль: исходные компоненты/геометрия/ресурсы Telegram с
фиксированным происхождением + локальные модели демонстрационных сообщений.
Никаких сетевых запросов, аккаунтов, login, push, звонков, платежей и клиентских
controllers в runtime редактора. Данные нужны для отрисовки; полную TL-схему и
ConnectionsManager подключать ради этих данных нельзя. Изменения зависимостей
компонентов нужно фиксировать отдельно от их исходного рисования — не подменять
это новым нарисованным «похожим» UI.

Артефакт должен проверяться на размер <=10,000,000 bytes, запрещённые зависимости
и native libraries до доставки. Точность интерфейса требует самостоятельной
проверки и не выводится из одного лишь успешного source/build guard.
