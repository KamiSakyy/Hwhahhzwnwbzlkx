# Forge 0.1 — initial implementation

Standalone new project; no pre-existing project files are used.

Scope: one UTF-8 HTML document with inline CSS/JavaScript, built into a signed Android APK without network access in the builder. Python, multi-file sites, arbitrary package IDs and custom app icons are not implemented. All generated APKs currently share a package ID and signing identity, so they replace one another. Only trusted input should be imported; JavaScript is enabled. Internet permission exists in the generated app; external resources still require a network.

Payload: AES-256-GCM, root ZIP entry payload.c beside classes.dex; native JNI library named libc++_shared.so. This is encryption at rest, NOT protection against a determined analyst. The static key can be recovered, including from the builder. The platform WebView and implementation can be identified. No claim of undetectability is made.

Signing key is generated by CI and embedded for offline APK signing; it is not a secret or a production publisher identity. Never use it for a sensitive distribution identity. CI additionally verifies the embedded template signature and enforces builder APK <= 3,000,000 bytes. Device install/build/run and rotation still need real-device testing. Gradle compilation alone does not establish runtime correctness.

Build outputs: handoff/Forge-0.1.apk and handoff/Forge-0.1-source.zip. Workflow refuses to overwrite existing output names. Later releases must use a new version and retain older artifacts.
